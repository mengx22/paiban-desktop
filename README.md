# 排班工作台 · Windows 桌面版 4.6.0

独立桌面窗口，保留现有排班规则和操作界面。无需打开浏览器、无需启动服务器，使用时无需安装 Node.js、Python，也无需联网。支持 Windows 10/11 64 位。

本仓库保存源码、测试和完整使用手册。内置名单与手册截图均使用张三、李四等虚构示例姓名，不代表真实人员或排班。实际排班存档、含数据免安装压缩包、Electron 运行文件与测试缓存不纳入 Git。通过源码运行或构建时，请先按下方“开发与打包”安装依赖；本地已有免安装程序时，可按“启动”章节直接运行。

## 启动

4.6.0 点击「导出与预览」打开独立窗口，在左侧编辑标题、注释与班次说明、本周备注，右侧实时按 A4 横向显示班表。标题和带教栏也可在预览表格中直接填写。Word 导出采用当前编辑内容，备注列自动填写每人的本周末欠休（含欠0），主任显示「—」；无有效结算时显示「待核算」。导出修改按周保存在本机，可恢复本周默认内容，不改变实际排班、工分或历史。CSV 明细也移至该窗口。预览为版式参考，Word/WPS 实际分页可能略有差异。

4.5.0 新增「导出 Word」：按照 CT-MRI 科样表导出可编辑的 DOCX，保留 A4 横向、斜线表头、序号、姓名、带教空栏、七天日期与班次、备注及底部说明。标题与日期随所选周更新，人员按当前顺序导出，本周末欠休显示在备注栏；无有效结算时标明「欠休待核算」。本周备注附在说明下方。CSV 按钮保留原留档格式。可在 Word/WPS 中编辑带教栏并打印。

双击文件夹中的 **启动排班软件.bat**，或直接打开：

`排班工作台\排班工作台.exe`

`排班工作台` 文件夹包含可直接运行的 EXE、配套文件和当前排班数据。`release` 内的含数据 ZIP 是打包时的快照。

完整操作说明见软件同目录的 `完整使用手册.pdf`（13页，含界面图）和 `完整使用手册.docx`（可编辑版）。内容覆盖快速上手、人员与职位规则、班次岗位、调班与锁定、历史衔接、工作量与欠休、导出预览、打印、备份恢复、迁移及常见问题。

## 本地保存与历史排班

- 人员、排班、手动锁定、岗位数量、工分、备注、欠休自动写入本地文件。
- 人员变动后如果暂时排不出完整班表，修改后的名单仍会保存。可以继续补人或调整类型，人员调齐后再生成排班。历史中保留上一次完整班表，清空名单后重启也会保留空名单。
- 点击 **历史** 可保存本周、读取以前的周排班、删除存档、导入旧排班 CSV。
- 切换周次前会保存当前周；已有记录的周次会恢复完整数据。
- 历史周数不设上限，不再在超过 104 周时自动删除旧记录。
- 同一周再次保存会更新该周记录；历史按周保存，不是每次编辑的版本记录。
- 班表左侧是上周末欠休，右侧是本周末欠休。首次使用时，点击「设置期初欠休」或左列余额输入非负数字（支持半分）；连续周会自动接续上周的期末。档案缺周时，可以手填新的期初。旧版文字欠休保留在备注中，不当作数字结转。
- 除主任外，每周基准为 5 工作量。超出 5 的部分增加欠休；低于 5 的部分抵扣已有欠休，每周最多抵扣 2，余额不低于 0。进修、下乡、出差计 1/天；周合计达到或超过 5 时不抵扣。生成和重排会在满足职位、岗位、锁定与夜班衔接的前提下尽量降低欠休。打印与 CSV 包括两列余额。
- 「人员配置 → 职位规则」打开独立窗口；「可排班次与上下限」管理职位，「班次工作量与欠休」管理各班次分值。白上、连班默认 0.5，白班、白签、白签1–4、白A/B/C/H、夜+白上默认 1。旧版内置班次的旧工分升级为新默认值，自定义班次的分值保留。
- 上周日夜班与本周一下夜班仍自动衔接，前提是上一周已有存档。
- 顶部“已保存”表示内容已写入本地文件；出现“未能写入本机存储”时请检查数据目录。

日常使用的数据保存在 `排班工作台\data\data.json`，`data` 文件夹与 `排班工作台.exe` 同级。点击 **数据备份 → 打开数据文件夹** 可查看实际路径。软件所在目录需有写入权限。

若软件目录内没有数据，首次启动会尝试从旧版的 `%APPDATA%\PaibanDesktop\data` 复制已有存档。旧文件会保留，后续修改写入软件目录。

其中 `data.json` 保存当前工作区、全部历史和名单方案；`data.json.bak` 保存上一次完整写入的数据。写入先使用临时文件、刷盘后替换，减少中途断电造成损坏的风险。主文件损坏时会尝试恢复 `.bak`，并保留损坏原文件、显示恢复提示。

## 备份、恢复与换电脑

随软件一起搬迁时，先关闭软件，再复制整个 `排班工作台` 文件夹。也可以使用下方的 JSON 备份流程。

1. 点击 **数据备份 → 备份全部数据**，选择 JSON 文件的保存位置。
2. 把该 JSON 文件复制到 U 盘或其他备份位置。
3. 在本机或另一台电脑打开桌面版，点击 **数据备份 → 从备份恢复 / 导入旧版数据**，选择 JSON 文件。
4. 核对文件名和历史周数，再点击“恢复数据”。

完整备份包含当前工作区、全部历史排班、名单方案、岗位数量、班次工作量、手动锁定、备注和欠休。恢复会替换当前全部内容，桌面版会先自动将当前数据保存到数据目录的 `恢复前备份` 子文件夹，然后重新加载。

CSV 适合用 Excel 查看或留档，不包含全部软件设置；需要完整迁移时请使用 JSON 备份。清除浏览器缓存不会删除桌面版数据。

若 `data.json` 和 `.bak` 均损坏，软件会停止加载并提示实际目录，不会以空数据覆盖原文件。关闭软件后先保留这两个文件，将它们改名移出数据目录，再启动并通过“数据备份”恢复之前导出的 JSON。无有效备份时应保留原文件用于修复。

## 从原来的浏览器版迁移

桌面版无法自动读取其他浏览器的站点数据。旧数据不会被自动删除。

1. 使用**以前保存排班的同一浏览器、同一地址**打开更新后的网页版。
   - 如果以前通过双击 HTML 使用，仍双击此处的 `index.html`。
   - 如果以前通过 `http://127.0.0.1:4173` 使用，可以临时启动静态服务，再在原浏览器访问相同地址。下方命令只复制迁移页面及其资源到临时目录。
   - 浏览器、浏览器用户、`localhost` / `127.0.0.1`、端口、文件路径不同，都可能对应不同的旧存储位置。
2. 点击网页版的 **数据备份 → 备份全部数据**，下载 JSON。
3. 在桌面版的 **数据备份** 中选择该文件恢复。

需要临时启动静态服务时，在软件根目录的 PowerShell 中运行以下命令。完成导出后按 `Ctrl+C` 停止服务。

```powershell
$paibanMigration = Join-Path ([IO.Path]::GetTempPath()) ('paiban-migration-' + [guid]::NewGuid())
New-Item -ItemType Directory -Path $paibanMigration | Out-Null
Copy-Item -LiteralPath 'index.html','assets','js','vendor' -Destination $paibanMigration -Recurse
python -m http.server 4173 --bind 127.0.0.1 --directory $paibanMigration
```

若只保留了之前导出的 CSV，可以通过 **历史 → 导入上一周 CSV** 补入历史；CSV 按姓名匹配人员，不会恢复旧版的全部设置。

## 自定义职位和班次

顶部可切换「周排班」「人员配置」「岗位与检查」。周排班页负责生成、查看和修改班表，人员配置页负责名单和职位规则，岗位与检查页可配置岗位人数并查看覆盖明细。

点击顶部「班次管理」，可在名称输入框中直接改名，也可新增班次或从每行点击「删除」。修改在点击「保存设置」后生效。删除会一并移除该班次的岗位人数、工分和相关职位资格及单班次上下限。如果当前班表用到了它，需要重新生成，历史记录仍可读取。

点「人员配置 → 职位规则」新增或改名职位。选择职位后，勾选工作日、周六和周日可排的班次，并设置每人每周总班次和单种班次范围。范围为 0–7 班，单种班次还受总上限和岗位数量限制。整周进修人员免除下限，休息和下夜班等状态不计入实际班次。

新增班次默认没有岗位。在「岗位数量」中设置需要几人，可在「职位规则 → 班次工作量与欠休」中设置分值。新增班次按普通班处理，原夜班改名后仍自动接下夜班。规则冲突时可以先保存设置，再调整人员和岗位后生成。

历史记录包含当周使用的职位、班次和上下限。读取旧周会载入该周设置，可用「撤销」回到刚才的工作区。完整备份包含这些设置。

## 原有功能

- 四类人员：科主任、签报告医师、写报告医师、夜班报告医师。
- 自动排班、手动调整并全周重排、撤销/重做、手动锁定。
- 工作日 / 周六 / 周日岗位数量分别配置。
- 班次工作量可调，自动统计个人工分。
- 名单方案、每周备注、个人欠休。
- 导出 UTF-8 CSV，原生打印对话框（A4 横向，可选择系统 PDF 打印机）。
- 默认科主任每周最多 2 个实际班，其他职位最多 5 个。自定义后按新范围检查。夜班衔接、每日岗位覆盖、职位与班次匹配仍由求解器检查。

排班细则见界面中的“规则说明”和 `rules.txt`。

## 开发与打包

日常使用不需要以下步骤。开发者需安装 Node.js 22.12+。

```powershell
npm install
node node_modules/electron/install.js
npm start
npm test
npm run build
```

依赖版本由 `package-lock.json` 固定。Electron 运行环境下载需要联网；最终打包好的程序离线运行。若 `.cache/electron-zip` 中已有对应版本的官方 ZIP，打包脚本直接使用它。

`npm run build` 在 `release` 输出供测试和打包的 Windows x64 程序目录。日常使用的程序在项目根目录的 `排班工作台` 文件夹。开发调试时可设置 `PAIBAN_DATA_DIR` 为隔离目录。

若已有完整的 `排班工作台` 程序目录，也可运行 `npm run build:portable`，复用本地 Electron 运行文件离线打包，不下载依赖、不复制实际存档。科室导出模板保存在 `assets/roster-template.js`，由 `scripts/prepare-roster-template.py` 从提供的 DOCX 提取。模板说明仅用于文档展示，不改变排班规则。

主要文件：

- `desktop/main.js`：桌面窗口、文件保存、备份对话框、打印、安全隔离。
- `desktop/preload.js`：界面与桌面文件存储的受限接口。
- `desktop/store.js`：原子写入、故障恢复、恢复前备份。
- `js/app.js`：排班界面、历史、备份与迁移。
- `js/backup.js`：完整备份格式与校验。
- `js/scheduler.js`：原有排班规则引擎。
- `tests/store.test.js`：持久化与恢复测试。

桌面版使用 Electron（MIT）及其附带许可证。求解器的第三方声明见 `vendor/THIRD-PARTY-NOTICES.txt`。软件不上传排班或人员数据，不包含遥测。
